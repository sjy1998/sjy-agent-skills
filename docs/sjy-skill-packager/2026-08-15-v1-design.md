# sjy-skill-packager V1 设计方案

- **状态：** 已批准 / V1 规划冻结
- **日期：** 2026-08-15
- **目标：** ChatGPT Web 个人 Skill 上传
- **仓库：** `sjy1998/sjy-agent-skills`
- **Skill 名称：** `sjy-skill-packager`

## 1. 项目概述

`sjy-skill-packager` 是一个小型个人 Agent Skill，用于把已经安装在 Codex 和/或 Claude 本地环境中的 Skill，打包为适合通过 ChatGPT Web Skill 上传界面提交的、确定性生成的 ZIP 文件。

预期用户流程：

```text
find-skills / GitHub
        ↓
npx skills add
        ↓
本地已安装的 Agent Skill
        ↓
sjy-skill-packager
        ↓
<skill-name>-chatgpt.zip
        ↓
用户通过 ChatGPT Web 上传
```

本工具**不负责**搜索、安装、更新、同步、翻译或发布 Skill。这些职责已经属于 `find-skills`、`npx skills`、Codex / Claude Skill 安装器或未来其他专用工具。

核心产品定义：

> `sjy-skill-packager` V1 是一个面向 OpenAI 生态的 Agent Skill 打包器。它负责定位一个已经安装在本地的 Skill，依据 OpenAI 当前 Skill 文档及 Agent Skills 开放规范进行校验，确认该 Skill 是否能够作为自包含的上传包，然后在**不修改源 Skill、不重写其行为**的前提下，生成并验证确定性的 ZIP 产物。

3. **Anthropic 官方 `skill-creator` 打包实现**

## 3. 已确认的平台模型

### 3.1 Agent Skill 结构

OpenAI 将 Skill 描述为一个至少包含 `SKILL.md` 的目录，并可选包含：

- `scripts/`
- `references/`
- `assets/`
- `agents/openai.yaml`

Agent Skills 开放规范允许 Skill 中存在上述目录之外的其他文件和子目录。

因此 V1 必须默认保留未知但属于 Skill 自身的文件，而不能因为“不认识”就认为它们无用。

### 3.2 ChatGPT Web 上传

OpenAI Help Center 当前说明，可以通过 ChatGPT Skills 的 **Create → Upload from your computer** 上传个人 Skill。上传后 ChatGPT 会执行安全扫描，结果可能是：

- 可用；
- **Needs Review**；
- **Blocked**。

V1 只负责准备上传包，不尝试复制、预测或模拟 ChatGPT 自身的安全扫描机制。

### 3.3 Codex 本地 Skill 位置

OpenAI 文档说明 Codex 会从 `.agents/skills` 中发现 Skill，包括：

- 从当前工作目录向上直到仓库根目录的项目级 `.agents/skills`；
- 用户级 `$HOME/.agents/skills`。

Codex 也支持通过符号链接指向 Skill 目录，并跟随其真实目标。

因此 V1：

- 将 `.agents/skills` 作为主要本地发现约定；
- 将 `.claude/skills` 作为兼容性来源。

### 3.4 `agents/openai.yaml`

`agents/openai.yaml` 是 OpenAI 官方支持的**可选** Skill 元数据文件。当前官方资料将其用于界面元数据、调用策略和工具依赖等产品级配置。

V1 不假设其中所有界面字段都对 ChatGPT Web 强制要求，也不假设不同 ChatGPT 表面的显示效果完全一致。

V1 行为：

- 文件存在：原样保留，并对已知官方结构做保守校验；
- 文件不存在：仍视为合法 Skill；
- V1 不自动生成 `agents/openai.yaml`；
- V1 不自动生成图标。

## 4. 设计原则

### P1. 官方标准优先

校验规则首先来自 OpenAI 和 Agent Skills 官方规范，其次才参考特定实现或社区校验器。

### P2. 保留源 Skill 行为

V1 不得自动改变源 Skill 的行为，尤其不能自动改写：

- `SKILL.md` Markdown 正文；
- 脚本；
- references；
- assets；
- Claude / Codex 工具或命令说明；
- MCP 工作流；
- 跨 Skill 行为。

### P3. 打包不等于迁移

打包器可以判断某个 Skill 在上传 ChatGPT 前需要人工适配，但必须明确报告该状态，而不是静默完成“迁移”或“翻译”。

### P4. 源 Skill 不可变

对打包器而言，源 Skill 是只读的。V1 中不存在任何写回源目录的路径。

由于 V1 不做内容规范化，因此不需要 staging 副本。如果未来版本增加显式 `--normalize`、元数据生成或修复功能，则必须在 staging 副本上处理，并继续禁止修改源 Skill。

### P5. 产物确定性

相同的输入文件字节和相同的打包规则，应产生相同的 ZIP 字节。V1 因此必须规范：

- 文件顺序；
- ZIP 时间戳；
- 权限元数据；
- 路径分隔符；
- 压缩方式。

### P6. 不确定性必须显式表达

打包器不能猜测多个本地 Skill 副本中“哪一个才是对的”，也不能猜测应如何修复行为层兼容性问题。

存在歧义或需要适配时，应返回明确状态。

### P7. V1 保持小型

V1 应保持为：

- 一个聚焦的 Agent Skill；
- 一个主要的确定性 Python 脚本。

不要引入 Skill Manager、Registry、生命周期平台、多目标发布框架等超出需求的系统。

## 5. V1 范围

### 5.1 V1 负责的能力

V1 只负责以下能力：

1. 接收 Skill 名称或明确目录路径；
2. 输入名称时，在本地已安装 Skill 中查找匹配项；
3. 解析根目录符号链接 / junction，并对指向同一真实目录的候选项去重；
4. 检测仍然存在的同名不同内容歧义；
5. 校验 Agent Skill 基础结构和 frontmatter；
6. 保守校验已存在的 `agents/openai.yaml`；
7. 校验包边界，例如嵌套链接和本地 Markdown 文件引用；
8. 排除已知构建垃圾和缓存；
9. 生成确定性 ZIP；
10. 重新打开 ZIP 并验证；
11. 返回稳定的机器结果，同时提供简洁的人类可读输出。

### 5.2 V1 明确不做的事情

V1 **不负责**：

- 搜索远程 Skill；
- 安装 Skill；
- 更新 Skill；
- 同步 Codex 和 Claude 副本；
- 直接抓取 GitHub URL 或 skills.sh URL；
- 把 Claude Skill 翻译成 OpenAI Skill；
- 自动重写 `${CLAUDE_SKILL_DIR}` 或其他平台表达式；
- 修复跨 Skill 依赖；
- 修改 Skill 正文指令；
- 修改脚本、references、assets 或模板；
- 生成 `agents/openai.yaml`；
- 生成图标；
- 执行恶意代码、密钥或 prompt injection 扫描；
- 模拟 ChatGPT 上传安全扫描；
- 自动上传 ZIP 到 ChatGPT；
- 为 Claude、Codex 或 ChatGPT Web 之外的目标打包；
- 创建 Release、PR、Registry、lockfile 或 Marketplace。

## 6. 用户交互

### 6.1 正常使用

正常流程不应要求用户额外回答问题。

示例：

```text
“把 ppt-master 打包给 ChatGPT”
“把 sjy-project-assistant 做成 ChatGPT 上传包”
“把 D:\skills\foo 打包成 ChatGPT Skill”
```

Skill 应自行解析输入，调用确定性脚本，并报告产物路径和结果。

### 6.2 什么时候允许询问用户

只有当脚本返回 `AMBIGUOUS` 时才需要用户选择。

`AMBIGUOUS` 表示：

- 找到了多个同名本地候选 Skill；
- 经真实路径去重后仍然是不同目录；
- 且它们的打包相关内容存在实质差异。

仅仅出现 warning / notice 不能成为询问用户的理由。

### 6.3 默认输出位置

用户没有指定输出目录时，V1 输出到：

```text
<current-working-directory>/dist/<skill-name>-chatgpt.zip
```

默认输出目录绝不能是源 Skill 目录。

如果目标 ZIP 已存在，必须：

1. 先构建新的临时 ZIP；
2. 验证新 ZIP；
3. 只有验证成功后才替换旧文件。

不能在新产物成功之前破坏已有的合法输出。

## 7. 架构

V1 保持有意的小型结构：

```text
skills/
└── sjy-skill-packager/
    ├── SKILL.md
    ├── scripts/
    │   └── package_chatgpt_skill.py
    └── references/
        ├── packaging-baseline.md
        └── chatgpt-web-packaging.md

tests/
└── sjy-skill-packager/
    ├── conftest.py
    └── test_*.py
```

职责划分：

- Skill 层负责理解用户意图和结果表达；
- Python 脚本负责确定性的文件系统操作、校验、ZIP 创建和产物验证；
- 仓库级测试放在 `tests/sjy-skill-packager/`，不进入可分发 Skill 包。

主脚本可包含以下聚焦的内部函数：

```text
find_skill_candidates()
resolve_skill()
validate_skill()
validate_openai_metadata()
validate_package_boundary()
should_exclude()
build_zip()
verify_zip()
package_skill()
```

这些只是 V1 的内部职责边界，并不意味着要拆成多个 Python 模块。除非实现规模或测试证明确有必要，否则不做过度模块化。

## 8. Skill 发现与解析

### 8.1 明确路径

如果输入能够明确解析为目录路径，则路径优先，跳过名称发现。

明确路径必须满足：

- 存在；
- 是目录；
- 解析根链接后包含 `SKILL.md`。

### 8.2 按名称发现

V1 按以下优先顺序收集候选项，但不会简单采用第一个结果：

1. 与当前工作目录相关的项目 / 仓库 `.agents/skills/<name>`；
2. `$HOME/.agents/skills/<name>`；
3. 项目级 `.claude/skills/<name>`；
4. `$HOME/.claude/skills/<name>`。

Codex 项目级发现应按照官方模型，从 CWD 向上检查 `.agents/skills`，直到能够识别出的仓库根目录。

V1 名称模式不主动搜索 `/etc/codex/skills` 等系统 / 管理员级 Skill；用户如果确实需要，可直接提供明确路径。

### 8.3 根目录 symlink / junction

Skill 根目录本身可以是符号链接或 junction。

每个候选项都先解析到真实目标，再去重。

多个候选路径如果最终指向同一个真实目录，则只算一个候选 Skill。

### 8.4 不同副本的处理

同一 Skill 名称如果仍有多个不同真实目录：

- 如果所有**打包相关文件集合和文件字节**完全一致，可以视为等价副本，选择发现优先级最高的一个，并记录 notice；
- 如果内容不同，返回 `AMBIGUOUS`，列出候选路径，不生成 ZIP。

内容等价比较不能依赖 mtime。

## 9. Agent Skill 校验

### 9.1 YAML 解析器

V1 使用 **PyYAML**，不自制不完整 YAML 解析器。

原因：

- Anthropic 官方 quick validator 已使用真实 YAML 解析器；
- `SKILL.md` frontmatter 和 `agents/openai.yaml` 可能使用合法但复杂的 YAML 写法；
- 对本工具而言，正确性比减少一个小依赖更重要。

V1 不自动安装 PyYAML。如果环境缺少 PyYAML，应返回 `FAIL`，明确说明缺少依赖，并给出最小安装指令。

### 9.2 `SKILL.md` 必检项

V1 依据 Agent Skills 规范严格校验：

- `SKILL.md` 存在；
- YAML frontmatter 分隔符存在并可解析；
- frontmatter 顶层为 mapping；
- `name` 存在且为字符串；
- `name` 长度为 1–64；
- `name` 只使用小写字母、数字和连字符；
- `name` 不能以连字符开头或结尾；
- `name` 不能包含连续 `--`；
- `name` 必须与父 Skill 目录名一致；
- `description` 存在、为字符串、非空、长度不超过 1024。

可选字段存在时校验：

- `license`：字符串；
- `compatibility`：非空字符串，最长 500；
- `metadata`：string key → string value 的 mapping；
- `allowed-tools`：字符串；其跨 Agent 支持仍属于实验性能力。

当前 Agent Skills frontmatter schema 之外的未知顶层字段视为校验错误。V1 只报告，不自动移动、删除或改写这些字段。

### 9.3 不复制社区特有的 YAML 自动修复

V1 不自动：

- 把 block scalar description 改成单行；
- 展平嵌套 metadata；
- 把 YAML list 形式的 `allowed-tools` 自动改成字符串；
- 截断字段；
- 仅因为第三方 validator 不接受尖括号就删除内容。

如果内容违反官方 Agent Skills 规范，报告官方规则对应的校验错误；如果官方允许但社区工具更严格，只能作为兼容性观察，不能伪装成官方强制规则，更不能自动重写。

## 10. `agents/openai.yaml` 校验

没有 `agents/openai.yaml` 时，本节直接通过。

文件存在时：

- 必须能被 YAML 解析；
- 顶层必须为 mapping；
- 对当前已知官方字段做保守类型校验；
- 不能仅仅因为 V1 不认识某个未来 OpenAI 字段就拒绝整个文件。

已知结构至少包括：

- `interface` 存在时应为 mapping；
- 已知 display / prompt / color / icon 字段存在时应为字符串；
- `icon_small`、`icon_large` 若是本地相对路径，应解析在 Skill 根目录以内，且文件必须存在；
- `policy` 存在时应为 mapping；
- `policy.allow_implicit_invocation` 存在时应为 boolean；
- `dependencies` 存在时应为 mapping；
- `dependencies.tools` 存在时应为 mapping 列表；
- 已知 MCP tool 条目的字段类型应符合官方结构。

V1 不从 Skill 正文中推断缺失的 MCP dependency，也不自动生成 dependency declaration。

状态：

- `agents/openai.yaml` YAML 语法错误 → `FAIL`；
- 已声明的本地图标路径越出 Skill 根目录或文件缺失 → `NEEDS_ADAPTATION`。

## 11. 打包边界校验

目标不是证明 Skill 在 ChatGPT Web 中一定能够完全等价运行，而是确认：**所有明确声明的本地资源是否能够被忠实、自包含地放进 ZIP。**

### 11.1 Skill 内部 symlink / junction

根 Skill 自身是 symlink 是允许的，并在发现阶段解析。

但 Skill 目录**内部**的 symlink / junction 在 V1 中不允许。

发现嵌套链接时返回 `FAIL`，不跟随链接打包，避免：

- 依赖本机文件系统；
- 意外打包 Skill 根目录之外的文件。

### 11.2 Markdown 本地链接

对明确属于 Markdown 本地文件链接的语法，V1 以该 Markdown 文件所在目录为基准解析目标，并校验是否位于 Skill 包内。

- 外部 URL：忽略；
- `mailto:`：忽略；
- 纯锚点链接：忽略；
- 本地目标越出 Skill 根目录：`NEEDS_ADAPTATION`；
- 本地目标位于 Skill 根目录内但不存在：`NEEDS_ADAPTATION`。

V1 不扫描普通文字中的任意 `../` 或疑似路径文本并擅自判断为依赖。只有确定性的文件引用形式才影响打包状态。

### 11.3 其他路径表达式

例如：

- `${CLAUDE_SKILL_DIR}`；
- 本地绝对路径；
- CLI 命令；
- hooks；
- 平台专属指令。

V1 不自动重写这些内容。

对于明显的可移植性风险，可以产生非阻断 notice，但除非存在官方规则或确定性包边界失败，否则不能直接断言 ChatGPT 无法运行。

## 12. ZIP 打包规则

### 12.1 采用 Anthropic 官方打包器作为基础实现参考

打包核心应吸收 Anthropic 官方 `package_skill.py` 的成熟行为：

- 解析源目录；
- 校验源和 `SKILL.md`；
- 打包前先验证；
- 递归枚举文件；
- 跳过已知构建垃圾；
- 保留 Skill 目录作为 ZIP 顶层目录；
- 使用 `ZIP_DEFLATED`；
- ZIP 创建失败时明确报错。

实现代码中的关键位置应注释说明哪些行为来自或改造自 Anthropic baseline。

### 12.2 排除规则

继承 Anthropic 的排除项：

- `__pycache__/`
- `node_modules/`
- `*.pyc`
- `.DS_Store`
- Skill 根目录下的 `evals/`

V1 额外排除明显不属于运行时 Skill 的开发缓存 / 元数据：

- `.git/`
- `.pytest_cache/`

V1 默认**不排除**：

- `tests/`
- `docs/`
- `examples/`
- `scripts/`
- `references/`
- `assets/`
- 未知目录。

这些排除只影响 ZIP 内容，不修改源文件。

### 12.3 ZIP 内部布局

默认产物：

```text
ppt-master-chatgpt.zip
└── ppt-master/
    ├── SKILL.md
    ├── scripts/
    ├── references/
    ├── assets/
    ├── agents/
    │   └── openai.yaml   # 仅源 Skill 本身存在时
    └── ...
```

“ZIP 顶层保留 Skill 文件夹”来自成熟 Skill 打包器的通用实现经验，但 OpenAI 当前公开 Help Center 没有完整明确 ZIP archive root 机制，因此必须通过 V1 的真实 ChatGPT Web 上传验收来最终确认。

### 12.4 确定性 ZIP

V1 采用确定性 ZIP 做法：

- 按 POSIX archive path 排序；
- ZIP 内路径统一使用 `/`；
- 使用 `ZIP_DEFLATED`；
- 使用固定 compression level；
- 写入 ZIP 格式允许的固定时间戳；
- 规范普通文件 permission metadata；
- ZIP 中不能出现源机器的绝对路径。

在同一 V1 实现及相同 Python / ZIP 压缩环境下，相同的打包相关输入字节应产生相同 ZIP 字节。

V1 不要求额外输出 SHA-256 sidecar；确定性主要用于测试和诊断。

### 12.5 原子替换

构建器先在目标目录生成临时 ZIP，验证后再替换最终：

```text
<skill-name>-chatgpt.zip
```

平台支持时使用原子替换。

如果验证失败，已有的合法旧 ZIP 必须保持不变。

## 13. 产物验证

ZIP 生成后，V1 必须重新打开并至少检查：

- `zipfile` 可以读取；
- 不存在绝对 archive path；
- 不存在 `..` 路径穿越条目；
- 所有条目都位于唯一的 `<skill-name>/` 顶层目录下；
- `<skill-name>/SKILL.md` 存在且可读取；
- 已排除的垃圾文件没有泄漏进 ZIP；
- 所有打包相关源文件在 ZIP 中的字节与源文件一致。

由于 V1 不修改 Skill 内容、也不生成元数据，因此所有被打包的源文件都必须保持 byte-identical。

## 14. 结果模型

脚本定义四种主要状态。

### `SUCCESS`

表示：

- Skill 成功解析且无歧义；
- 通过结构与边界校验；
- ZIP 构建并验证成功。

允许携带非阻断 `notices`。

### `AMBIGUOUS`

存在多个实质不同的同名本地 Skill 副本。

- 不生成 ZIP；
- 返回候选路径；
- 调用方应询问用户选择哪一个。

### `NEEDS_ADAPTATION`

Skill 结构可理解，但无法在不修改内容 / 行为的情况下成为自包含包。

例如：

- 明确本地文件依赖越出 Skill 根目录；
- `agents/openai.yaml` 声明的本地图标缺失。

V1 不自动修复。

### `FAIL`

出现确定性的结构、依赖或打包错误，例如：

- Skill 目录不存在；
- 缺少 `SKILL.md`；
- YAML 无法解析；
- 必填 Agent Skills 元数据非法；
- `agents/openai.yaml` 语法错误；
- Skill 内部存在 symlink / junction；
- 缺少 PyYAML；
- ZIP 构建失败；
- ZIP 验证失败。

## 15. CLI 与 Agent 调用契约

主脚本保持最小接口：

```text
python scripts/package_chatgpt_skill.py <skill-name-or-path> [--output-dir DIR] [--json]
```

V1 不新增：

- `--fix`
- `--normalize`
- `--target`
- `--platform`
- `--strict`
- `--sync`
- `--upload`

### 人类输出

默认 stdout 输出简短结果摘要，适合终端用户直接阅读。

### JSON 输出

`--json` 为 Codex / Claude 编排提供稳定对象，例如：

```json
{
  "status": "SUCCESS",
  "skill": "ppt-master",
  "source": "C:/Users/.../.agents/skills/ppt-master",
  "artifact": "D:/project/dist/ppt-master-chatgpt.zip",
  "notices": []
}
```

规则：

- `AMBIGUOUS` 包含 `candidates`；
- `NEEDS_ADAPTATION` 和 `FAIL` 包含结构化 `issues`；
- `FAIL` 和 `NEEDS_ADAPTATION` 使用非零退出码；
- `AMBIGUOUS` 也使用独立非零退出码，避免调用方把它误认为成功。

具体数字退出码在实施计划中锁定，并必须稳定、可测试。

## 16. 依赖策略

V1 运行时依赖仅包括：

- Python 3；
- PyYAML。

其余使用 Python 标准库，例如：

- `pathlib`
- `zipfile`
- `tempfile`
- `hashlib`
- `json`
- `argparse`

Skill 不自动安装 Python 包。如果缺少 PyYAML，只报告最小安装方式并停止，环境变更决定权留给用户 / Host。

## 17. 测试策略

### 17.1 单元与文件系统集成测试

V1 至少覆盖：

1. 最小合法 Skill 可以成功打包；
2. 保留 `scripts/`、`references/`、`assets/`、Skill 自带 `tests/`、docs/examples 及未知文件；
3. 排除 Anthropic baseline 垃圾和 V1 新增缓存项；
4. 拒绝缺少 `SKILL.md`；
5. 拒绝无法解析的 frontmatter YAML；
6. 拒绝缺失 / 非法 `name` 和 `description`；
7. 校验目录名匹配及 Agent Skills 命名规则；
8. 校验可选 `license`、`compatibility`、`metadata`、`allowed-tools`；
9. 已存在的合法 `agents/openai.yaml` 必须 byte-for-byte 保留；
10. 拒绝语法错误的 `agents/openai.yaml`；
11. 校验本地 OpenAI 图标路径，但不要求图标一定存在于所有 Skill；
12. 解析指向合法 Skill 的根 symlink；
13. 两条发现路径指向同一 Skill 时去重；
14. 同名但内容不同的副本返回 `AMBIGUOUS`；
15. 拒绝 Skill 内部 symlink / junction；
16. Markdown 本地链接越出根目录时返回 `NEEDS_ADAPTATION`；
17. Markdown 本地链接目标缺失时返回 `NEEDS_ADAPTATION`；
18. 忽略外部 URL 和纯 anchor；
19. ZIP 只有一个正确 Skill 顶层目录；
20. Windows 上 ZIP entry 仍使用 POSIX `/`；
21. 同环境、同输入重复打包产生 byte-identical ZIP；
22. 新 ZIP 验证成功前不替换旧输出；
23. 所有 ZIP 内源文件与源字节一致；
24. 四种状态的 JSON shape 均稳定。

### 17.2 源 Skill 不可变测试

关键回归测试必须：

1. 打包前记录源 Skill 文件清单与 hash；
2. 执行打包；
3. 打包后重新记录；
4. 要求前后完全一致。

### 17.3 ChatGPT Web 真实集成验收

V1 不视为完成，直到至少完成：

- 一个刻意设计的最小测试 Skill；
- 一个有代表性的真实已安装 Skill；

并通过 ChatGPT Web 手动上传测试。

验收内容：

- ChatGPT 接受 ZIP 上传；
- 经平台扫描后 Skill 可以被使用（受平台安全审查结果约束）；
- `SKILL.md` 指令能够被 Skill 使用；
- 代表性的 supporting resources 可访问；
- 分别测试不含 `agents/openai.yaml` 与本身已含该文件的 Skill；
- 用真实上传确认 ZIP 顶层目录布局。

如果真实上传暴露出公开文档未说明的 ZIP wrapper 要求，V1 可以调整 ZIP 包装层；如果需要改写 Skill 行为，则必须重新打开 Design，而不能直接在实现阶段偷偷改变产品定义。

## 18. 社区实践：采用与拒绝

### Anthropic 官方打包器

**采用：**

- 打包前校验；
- 排除垃圾；
- 递归打包；
- Skill 文件夹作为 ZIP 根；
- `ZIP_DEFLATED`；
- 明确失败行为。

**调整：**

- 输出扩展名 / 文件名；
- 确定性 ZIP 元数据。

### Yaniv Skill Packager

**采用：**

- 已安装 Skill 可能需要按名称发现；
- 跨平台打包需要明确路径纪律。

**V1 拒绝：**

- 对 Markdown 全局替换 `${CLAUDE_SKILL_DIR}/`。

### Universal Skills Manager

**采用：**

- Cloud 上传前应先校验；
- 结构化 diagnostics 有价值。

**V1 拒绝：**

- 自动 frontmatter fixer；
- 自动移动未知字段；
- 自动展平 metadata；
- 仅为满足社区解析器而自动重写 description。

### Freeflow ChatGPT Web Skills

**采用：**

- 包边界校验；
- symlink 谨慎处理；
- 确定性 ZIP；
- 真实 ChatGPT Web 上传作为验收。

**不直接泛化：**

- 强制 icon / OpenAI metadata；
- 社区观察到但未由 OpenAI 官方确认的包大小 / 文件数限制。

### Joel Fernandes ChatGPT Packager

**采用：**

- ChatGPT 目标产物命名清晰；
- 区分源内容与分发关注点。

**V1 拒绝：**

- 自动重写 frontmatter；
- 对所有 Skill 强制生成 `agents/openai.yaml`。

## 19. 成功标准

用户可以直接说：

```text
把 ppt-master 打包给 ChatGPT。
```

如果本地 Skill 合法且自包含，则无需人工寻找路径，最终得到：

```text
dist/ppt-master-chatgpt.zip
```

同时必须满足以下不变量：

1. 源 Skill 完全不变；
2. 官方 Agent Skills 校验规则不能被社区假设削弱；
3. 社区观察不能被错误标记为 OpenAI 要求；
4. 行为层不兼容必须报告，而不是静默重写；
5. ZIP 可确定性生成并可验证；
6. 产物必须经过真实 ChatGPT Web 上传测试证明。

## 20. 延后到后续版本的问题

以下能力明确推迟，不属于 V1 未解决的模糊项：

- 自动生成 `agents/openai.yaml` 和 icons；
- 基于 staging 的显式 `--normalize` / `--fix` 模式；
- Claude / Codex 专属命令和环境变量的 portability lint；
- 自动适配跨 Skill 引用；
- ZIP checksum / provenance manifest；
- OpenAI 未来正式公布后的 ChatGPT 文件数 / 包大小限制执行；
- 多 Skill 批量 ZIP；
- 自动上传 ChatGPT；
- ChatGPT Web 之外的其他打包目标。

任何后续新增能力都必须继续保持“打包”和“行为迁移”是两个不同职责，除非未来 Design 明确重新定义产品边界。
